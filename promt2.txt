============================================================
PRIMARY OBJECTIVE
============================================================

Transform Beta into a system consisting of:

1. A lightweight Render backend.
2. A custom Virtual AI API.
3. Five Groq-powered AI agents operating internally as ONE logical AI.
4. An AI orchestrator responsible for communication between the five agents.
5. Internal shared task/context memory.
6. Multi-agent reasoning, critique, verification, and synthesis.
7. A Windows Browser Client.
8. Selenium + ChromeDriver + Chrome running ONLY on Windows.
9. Secure WebSocket communication between Render and Windows.
10. The ability for the Virtual AI to request browser operations.
11. A final unified AI response exposed through the Beta API.
12. Architecture optimized for Render Free with approximately 512 MB RAM.

The external user must see Beta as ONE AI model/API.

The user should NOT need to know that five separate Groq agents are operating internally.

============================================================

============================================================

The backend is intended to run on a Render Free instance with approximately 512 MB RAM and limited CPU.

Therefore:

Render MUST NOT run:

- Chromium
- Chrome
- ChromeDriver
- Selenium browser automation
- local LLM inference
- downloaded LLM weights
- GPU workloads

All browser automation must run on the user's Windows machine.

All AI inference must be performed through external Groq APIs.

Render should primarily perform:

- FastAPI

- Virtual AI orchestration
- HTTP requests to Groq
- WebSocket communication
- authentication
- task management
- database operations
- lightweight state management
- JSON processing
- logging
- configuration

Keep the Render application as lightweight as possible.

============================================================
VIRTUAL AI MODEL
============================================================

The central feature is a Virtual AI Model.

Beta must expose one logical AI to external clients.

Internally, Beta consists of five Groq-powered agents.

The external client should see something similar to:

model = "beta-virtual-ai"

The user sends:

POST /v1/chat/completions

Example:

{
  "model": "beta-virtual-ai",
  "messages": [
    {
      "role": "user",
      "content": "Solve this task..."
    }
  ]
}

The external API must return one coherent response.

Internally, the request is processed by the multi-agent system.

The internal architecture must remain hidden from normal API users.

============================================================
FIVE AI AGENTS
============================================================

Create five logical AI roles.

AGENT 1:
ARCHITECT / PLANNER

Responsibilities:

- understand the user request
- break complex tasks into subtasks
- determine strategy
- determine whether browser automation is needed
- create an execution plan

AGENT 2:
RESEARCHER / ANALYST

Responsibilities:

- analyze available information
- inspect evidence
- identify missing information
- research using available tools/data
- provide findings to the other agents

AGENT 3:
SOLVER

Responsibilities:

- solve the actual task
- generate candidate solutions
- propose browser actions when needed
- reason over information supplied by other agents

AGENT 4:
CRITIC / VERIFIER

Responsibilities:

- challenge assumptions
- detect errors
- detect unsupported conclusions
- verify important claims
- identify missing evidence
- request additional work when necessary

AGENT 5:
JUDGE / SYNTHESIZER

Responsibilities:

- evaluate all available reasoning
- determine the best solution
- resolve disagreements
- decide whether additional deliberation is required
- produce the final coherent answer

These roles should be configurable.

Do not hard-code the implementation so that changing models later requires rewriting the architecture.
