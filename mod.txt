

You are working directly on the existing GitHub repository:

https://github.com/dynamite-ai-coder/Beta

Your task is to refactor the existing Beta project into a production-ready distributed architecture consisting of:

1. A lightweight Render backend.
2. Groq AI running exclusively through the Render backend.
3. A Windows Browser Agent running locally on the user's Windows computer.
4. Selenium + ChromeDriver + Chrome running ONLY on the Windows computer.

IMPORTANT ARCHITECTURAL REQUIREMENT:

Render must NOT run Chromium, ChromeDriver, Selenium, or any browser automation.

The Windows client must run the browser locally.

Termux/Android support is completely out of scope for this refactor. Focus only on Windows.

There will always be exactly ONE browser session, ONE Chrome instance, and ONE active browser window on the Windows client.

The main objective is to remove Chrome/Selenium memory usage from Render so the backend can comfortably operate within the 512 MB RAM limitation of the Render free instance.

Do NOT blindly rewrite the project.

First inspect the entire repository and understand the existing architecture, then modify it incrementally while preserving existing functionality wherever possible.

==================================================
BROWSER STARTUP
==================================================

When the Windows client starts:

1. Start the client.
2. Load configuration.
3. Authenticate with Render.
4. Establish WSS connection.
5. Start Chrome.
6. Start Selenium/ChromeDriver.
7. Verify that Chrome is ready.
8. Send BROWSER_READY to Render.
9. Wait for tasks.

The normal state should be:

CLIENT ONLINE
+
BROWSER READY
+
WAITING FOR TASK

==================================================
BROWSER CRASH RECOVERY
==================================================

If Chrome or ChromeDriver crashes:

1. Detect the failure.
2. Report BROWSER_ERROR.
3. Stop/kill the broken browser process.
4. Clean up Selenium.
5. Restart ChromeDriver.
6. Restart Chrome.
7. Verify the new session.
8. Send BROWSER_READY again.

Do not require the user to manually restart the client.

20. If WebSocket disconnects, the Windows client reconnects automatically.
21. If Render restarts, the client reconnects automatically.
22. Render never runs Chrome.
23. Groq API key never leaves Render.
24. Render uses significantly less RAM than the current architecture.
